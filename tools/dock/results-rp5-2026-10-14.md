ROOT CAUSE (cycle1 trace, monotonic s; verified in source afterwards): 123.347 DRM suspend disables the DP
bridge (link off 123.365) -> 123.412 the dock sends a DP Attention VDM (SVID ff01, status 0x19a = HPD high +
IRQ_HPD), delivered: tcpm -> dp_altmode -> drm oob hotplug -> msm_dp hpd_notify ignores it ("HPD already on")
-> 123.664 suspend_noirq masks the PMIC irqs -> the dock sends the Attention AGAIN (header 0x258f, overnight
0x238f) -> the PD PHY takes it into its rx buffer (hardware GoodCRC) and the buffer token flips to
software-owned (RX_ACKNOWLEDGE 0x174b = 01) -> msg-rx edge masked. spmi-pmic-arb has IRQCHIP_MASK_ON_SUSPEND
and qpnpint_irq_unmask() writes LATCHED_CLR + EN_SET together, so the latched edge is WIPED at resume
(LATCHED/PENDING read 0 afterwards). Nobody reads the buffer: every PD transmit -EBUSY "RX message pending",
every later rx dropped = PD dead until replug. Resume: dwc3 124.277, DP bridge enable 124.623 -> 320 AUX
timeouts -> link training fails 128.2-129.97 -> connector "connected/enabled" with no link, thaw 133.56 (a
docked resume stalls ~9 s on the AUX timeouts). The lost Attention is the sink's "read my link status /
retrain" request. Vendor kernel (msm-4.19 qpnp-pdphy.c): sig-rx and msg-rx are wake irqs, a PD message wakes
the SoC, Android re-sleeps by itself; its DP driver puts the sink in D3 before suspend (upstream only for
sink_count == 0) and services IRQ_HPD with link maintenance.

Fix = kernel 27, patch 40-holodor/0724 (ours): PM callbacks on the qcom-pmic-typec platform driver.
resume_noirq reads INT_LATCHED_STS of the typec + pdphy peripherals (log), complete() delivers a message left in
the PD PHY rx buffer to tcpm (receive on + token software-owned can only be an unread message) and lets tcpm
re-read CC/VBUS (the same calls the port irq handler makes; a CC/VBUS edge during sleep is lost the same way).
Also fixes pd_receive handing tcpm an unread pd_message on an out-of-range RX_SIZE and leaving the buffer
wedged. Deliberately NOT the vendor wake-irq design: a PD message waking a Steam device costs 10 min awake per
dock Attention (the dock sends one whenever the DP link changes); wake behaviour unchanged. UNTESTED at the
time of writing; next: E4 (sleep with the 010-usb-host hook disabled, kernel 26) to see whether the dock's
AUX survives when the host never leaves, then kernel 27 cycle: expect the buffered Attention delivered at
complete() ("PD message (header 0x..) received during suspend") and PD alive after the wake; whether the
picture returns depends on the AUX (if the wedge killed it, the resume modeset's own link training brings it
back; else part (b): Type-C IRQ_HPD -> msm_dp link maintenance, and the vendor's D3-before-suspend).
